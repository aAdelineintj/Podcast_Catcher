## 二、已砍功能明细（2026-09-19，P0 砍需求清单）

### 2.1 为什么砍

1. **坏的功能比没有更伤信任**：上一句/下一句当时是「按时间估算位置」跳转，
   不是真正的句子跳转 —— 按钮在、点了也能跳，但跳不准，而用户不知道它不准。
2. **不是 P0**：P0 目标只有四个字 ——「能上传、能转写、能看、能存」。
   先把主链路跑通，其余一律让路。
3. **顺带清死代码**：`Player.tsx` 全仓库无任何引用，一起删掉。

### 2.3 砍掉的功能 → 将来若要重做的正确起点

- **上一句 / 下一句**：~~原起点是让后端补 `end`/`startSeconds`~~ **已于 2026-10-14 恢复**，实现见 §2.4。
  实际未等新字段：直接复用 `segments[i].start`（转写产出的真实时间戳字符串），与现有高亮逻辑同源，
  所以是**准确跳句**，不是当年「按时间估算位置」那种跳不准的版本。
- **RSS 导入 / 导出**：`产品需求.md` 里本来就被归为「后做」，无技术债，重做即恢复。

### 2.4 2026-10-14 恢复：上一句 / 下一句

**做法**：不新增后端字段，直接复用现有 `podcast.segments[i].start`。

- `src/app/podcast/[id]/page.tsx`
  - 复用已有的 `activeIndex`（由 `currentTime >= parseTimeToSeconds(segments[i].start)` 推导，即真实句起点）。
  - 新增 `goToSentence(i)`：`playerRef.seek(segments[i].start)`（seek 即起播）；
    `goToPrevSentence` / `goToNextSentence` 在边界做 clamp（首句禁用上一句、末句禁用下一句）。
  - 键盘 ←/→ 通过 `navRef` 拿最新闭包，避免 window 监听者过期。
  - `prevSentenceDisabled` / `nextSentenceDisabled` 两个 useMemo 控制按钮可用态。
- `src/components/BottomPlayer.tsx`
  - 新增 `ChevronLeft` / `ChevronRight` 两个按钮（播放键左右各一），带 `title="上一句（←）"` / `title="下一句（→）"`；
    禁用态 `opacity-30 cursor-not-allowed`。
  - 新增 `onPrevSentence` / `onNextSentence` / `hasPrevSentence` / `hasNextSentence` 四个 props。
- **为什么这次准确**：高亮与跳转都基于 `segments[i].start` 真值，`Transcription` 在 `active` 变化时会
  `scrollIntoView` 自动滚动跟随，因此点「下一句」= 跳到该句起点 + 自动高亮 + 自动滚到中间，体验一致。
- **验证**：`npx tsc --noEmit` 源码零错误（仅 `.next/types` 旧构建噪声）；页面视觉需芸娜本人在浏览器确认。

### 2.5 2026-10-14 恢复：单句循环 n 次

**做法**：在「上一句/下一句」基础上加循环控制，不新增后端字段。

- `src/components/BottomPlayer.tsx`
  - 新增 Repeat 按钮（`loopEnabled` 开关）+ 开启时显示次数条 `1/2/3/4/5/∞`（`loopCount`，`-1`=无限）。
  - `loopAnchorRef`（当前循环的句索引）+ `loopPlaysRef`（已播放遍数）；`useEffect([activeIndex, loopEnabled])`
    在开循环或切到新句子时把锚点钉到 `activeIndex` 并重置遍数。
  - `timeupdate` 里：播放到 `sentenceBoundaries[anchor].end - 0.06` 时回到句首重播；
    有限遍数播完则 `pause()` + 关循环（`onLoopFinished`）；无限则一直重播。
- `src/app/podcast/[id]/page.tsx`
  - `loopEnabled` / `loopCount` 两个 state；新增 `sentenceBoundaries` memo（`end = 下一句起点，末句用音频总时长`）。
  - 把状态与边界传给 BottomPlayer，并把「播完关循环」回填 `setLoopEnabled(false)`。
- **语义统一**：次数 `1` = 自动只播这一句后停在句尾（即当年另列的「自动只播这一句」）；
  `2~5` = 跟读遍数；`∞` = 无限单句循环。一个控件覆盖两个原砍功能。

**验证**：`npx tsc --noEmit` 源码零错误；线上健康检查 200/404（新版本 `07f1b084…`）。

## 三、更早一轮砍掉的「多租户配套」（2026-09-16）

定位从「公开推广给陌生用户」回退为**个人自用工具**后，以下整条路线作废。
它们**不是待办**，也**不要因为上了云就把它们捡回来**。

| 原计划要做 | 结论 | 原因 |
|---|:---:|---|
| Supabase Auth 账号体系 | ❌ **不做** | 只有自己用 |
| 用量配额 + `usage` / `ip_usage` 表 | ❌ **不做** | 无滥用风险 |
| 任务队列（Redis / Celery） | ❌ **不做** | Postgres 一张表 + `FOR UPDATE SKIP LOCKED` 就够 |
| SSE 替代轮询 | ❌ **不做** | 体验优化，非必需 |
| 隐私政策 / 用户协议 | ❌ **不做** | 无第三方用户数据 |
| 人机验证 | ❌ **不做** | 无注册入口 |
| 多租户数据隔离 | ❌ **不做** | 单用户 |

> 注意区分：2026-09-19 的「上云」**只反转了数据持久化三条**（对象存储 / 数据库 / 历史收藏迁出 localStorage），
> **没有**反转多租户那批。「单用户、无账号、无配额」依然成立。

## 五、上线状态（2026-10-14）

- **线上入口**：`https://podcast-catcher.yuuh88.workers.dev`
  —— 2026-10-14 迁移到 **Cloudflare Workers（vinext）** 并部署成功，读链路（PostgREST + Storage 签名）已验收通过。
- **浏览器打开可能报 `ERR_CERT_COMMON_NAME_INVALID`**：这是本机 **DNS 投毒**，不是部署问题。
  解法：把域名钉到真实 IP（`104.21.36.169`）写入 `/etc/hosts`，或在 Chrome 里打开「使用安全 DNS」(DoH)。
- **架构**：本机 Whisper 转写 + Supabase 持久化 + 前端上云 + 本机 worker 轮询取任务。
  算力留本机、云端只存数据和调度 —— 这是能**完全免费**的原因。
